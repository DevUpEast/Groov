# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

**Start dev server (Expo Go / QR code):**
```powershell
npm start
```

**Run on specific platform:**
```powershell
npm run android   # Android emulator (AVD "groov_pixel") or device
npm run ios       # iOS simulator (macOS only; this machine is Windows, use EAS builds)
npm run web       # Browser
```

> On Windows, if `npm` is not found in a new terminal, refresh PATH first:
> `$env:PATH = [System.Environment]::GetEnvironmentVariable("PATH","Machine") + ";" + [System.Environment]::GetEnvironmentVariable("PATH","User")`

> Always refer to versioned Expo docs at https://docs.expo.dev/versions/v54.0.0/ before writing Expo-specific code.

**Local env:** `.env.local` (gitignored) holds `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY`. `EXPO_PUBLIC_APTABASE_KEY` turns on anonymous product analytics via `src/utils/analytics.js` (`track(Events.X, props)`; no-op without the key; events are counts only, never names/ids; the privacy policy lists Aptabase). The same values are inlined in `eas.json` for production builds. `EXPO_PUBLIC_SENTRY_DSN` turns on crash reporting via `src/utils/sentry.js` (Sentry org `isaac-23`, project `groov`; the DSN is public and lives in eas.json); without it Sentry is a no-op. Source-map upload uses the `@sentry/react-native/expo` plugin in app.json (org `isaac-23`, project `groov`) plus the `SENTRY_AUTH_TOKEN` EAS environment variable (set for production and preview); local builds skip the upload because the token is not present locally.

**Quick compile check (no device):** `npx expo export --platform web --output-dir $env:TEMP\groov-web-export`

## Stack

- **Expo SDK 54** / React Native 0.81.5 / React 19.1.0, JavaScript (tsconfig exists but all files are `.js`)
- No file-based routing; no React Navigation library (custom pager in `App.js`)
- **Supabase** for auth and cloud sync (`@supabase/supabase-js`), AsyncStorage as the local-first store
- Sound kit (plan §2.11, F-04b): a synthesised "soft kalimba" (partials 1 / 2.76 / 5.4 plus a 9x click, each with its own decay) on one C-major pentatonic ladder. `src/utils/synth.js` (pure synth + WAV encoder) and `src/utils/soundKit.js` (pure: `SOUND_DEFS`, `EVENT_SOUNDS` event → sound or explicit null, `soundIdFor(event, { n } | { step, goal })`; daily check-offs climb `H(n)`, counters climb `C(k, G)` and the goal step is C6→E6, never lower; atMost limits get a flat quiet C5 tick and no sound on the tap that breaks the limit) are shared by the app and `node scripts/render-sound-kit.mjs` (writes the 12 listening WAVs + a day sequence to `research_notes/uiux/review/sounds/`, no expo-audio). `src/utils/sounds.js` `playSound(id)`: native renders each sound once to `cacheDirectory/groov-snd-<id>-<hash>.wav` (hash of the definition, so kit edits re-render; byte-identical to the Node render) and plays it with expo-audio through a pool of players, one per sound (C-06a: a replay is `seekTo(0)` + `play()`, never a new `createAudioPlayer`; at most 3 sound at once, a new one pauses the oldest; at most `MAX_POOL` 10 kept, the least recently used idle one is released; prewarm creates the priority sounds' players unplayed). AppContext starts `feedback.prewarmSounds()` once loaded: after `InteractionManager` + 4 s it renders the kit (chord, habit-1, goal, challenge, fanfare first, one per macrotask, postponed while any feedback event or sound happened in the last 1.5 s) and sweeps stale `groov-snd-*` files; a missing sound still renders on demand. Writes go to `.tmp` then rename, a wrong-size cache file is re-rendered, a write/play failure mutes that id for the session and warns once; web plays the same samples through a Web Audio buffer. No audio assets. The audio mode is iOS ambient (`playsInSilentMode: false` + `mixWithOthers`), so the silent switch mutes the kit
- Haptics and event sounds go through `src/services/feedback.js` only (the only importer of `expo-haptics`; a source test enforces it). Callers name the event, `feedback.play(EVENTS.habitDone)` (`habit.done`, `counter.step`, `habit.undone`, `challenge.claimed`, `day.complete`, `milestone`, `trophy`, `markRest`, `selection`, `toggle.on/off` via `feedback.toggled(v)`, `longPress`, `refused`, `error`, `destructiveConfirm`), and the plan §2.10 map picks the call: iOS impact/notification/selection, Android only `performAndroidHapticsAsync` with a `Platform.Version` fallback chain (Confirm/Reject/Gesture_End need API 30, Segment_Tick/Toggle_* API 34, else Context_Click/Clock_Tick/Long_Press, else nothing; never `Vibration`). Each event's sound comes from `soundKit.js` (pass `{ tone }` for the ladder note; `sound.preview` is the Settings → Sounds preview; Mark the rest plays its chord at +750; tap sounds are limited to one start per 60 ms, celebrations never dropped). AppContext calls `feedback.configure({ haptics, sound })` on load, on settings changes and synchronously in `updateSettings`, so callers never check `settings.hapticsEnabled`/`soundEnabled`. 40 ms haptic rate limit; `day.complete` lands at +750 ms and `challenge.claimed` at +250 ms by default (`{ delay }` overrides). `play(event, { at })` takes the tap time: the delay counts from it, and each log entry records `offset` (from the tap), `target` (the planned beat) and `drift` (offset - target). Settings → Dev tools → Feedback log shows the last 50 entries as `+766ms @750 Δ+16 day.complete android:confirm`; `quietIn()` is the time left in the current 1.5 s moment; on the emulator `adb shell dumpsys vibrator_manager` lists each `performHapticFeedback(constant=N)`
- expo-notifications for local per-habit and global reminders. Categories give reminders Done / Snooze 1h buttons (handled in AppContext via `listenForNotificationResponses`); per-habit reminders back off after 3 consecutive missed days (`reminderDueWithBackoff`); AppContext schedules through `requestReminderSchedule` (debounced by `REMINDER_SCHEDULE_DEBOUNCE_MS`, one pass at a time, stale passes stop before their next OS call) so an older pass can never re-add a reminder a newer one cancelled; the evening smart check-in (`requestEveningCheckIn`) runs on the same chain, and the AppProvider unmount (sign-out) queues `clearRemindersOnSignOut` so the old user's reminders stop firing; the OS permission dialog is always preceded by `NotificationPrimer` via `ensureNotificationPermission()` (the primer is rendered above the onboarding gate in `App.js`, so onboarding can await it); AppContext exposes `notificationPermission` (refreshed on load and on foreground), and while permission is missing Settings shows the master row and every stored-on reminder as "Off · Tap to allow" (the master row asks; child switches are dimmed); global reminders (`DEFAULT_REMINDERS` in `src/utils/settings.js`, with `migrateSettings`) start off on a new install; the app badge shows habits left today
- `@react-native-community/datetimepicker` (8.4.4) for reminder times
- react-native-svg for the progress ring; charts and heatmap are hand-built (no chart library installed)
- expo-apple-authentication, expo-web-browser, expo-linking, expo-crypto for social sign-in

## Architecture

**Entry point:** `index.js` → `registerRootComponent(App)` → `App.js`

**Gating order:** `ErrorBoundary` → `AuthProvider` → `AuthGate` (no session renders `AuthScreen`) → `AppProvider` (keyed by user id) → `OnboardingScreen` until `hasOnboarded` → tab navigator.

**Navigation:** Custom slide navigator in `App.js`. Deep links (`src/utils/links.js`): `groov://today|progress|challenges|habits|settings`, `groov://habits/new`, `groov://habit/<id>` (detail sheet), `groov://habit/<id>/done`, `groov://dev/design` (token preview, dev/mockup only); AppContext parses them (initial URL + `url` events + `expo-quick-actions` home-screen shortcuts) into `requestedTab` and a `pendingRoute` the Habits screen consumes. All 5 screens are rendered simultaneously in a horizontal `Animated.View`; inactive screens have `pointerEvents="none"` and are hidden from screen readers (`importantForAccessibility="no-hide-descendants"`, `accessibilityElementsHidden`, and `aria-hidden` for web). Android back: every overlay is a `Modal` with `onRequestClose` (it consumes the event); otherwise a `BackHandler` in `AppNavigator` sends a non-Today tab to Today, and back on Today exits. Navigation is driven by swipe gestures (`PanResponder`) and tab-bar taps. Tab order: Today → Progress → Challenge → Habits → Settings. Screens can request a tab via `requestedTab`; swiping is disabled while `modalOpen`.

**Auth:** `src/context/AuthContext.js`. Email/password (with OTP password reset), Sign in with Apple (iOS/iPadOS only, native sheet + `signInWithIdToken` with nonce), Google (Supabase OAuth in the system browser, PKCE, redirect `groov://auth/callback`), and guest accounts (`signInAnonymously`; Supabase anonymous sign-ins + manual linking are enabled). Guests link later from Settings via `LinkAccountSheet` (`linkEmail` = `updateUser`, `linkWithGoogle`/`linkWithApple` = `linkIdentity`), keeping the same user id. Exposes `authProvider` (`email|apple|google|anonymous`), `isAnonymous` and `appleAvailable`. A pg_cron job purges anonymous users idle for 90 days. Account deletion calls the `delete-account` edge function. Setup steps: `docs/AUTH_SETUP.md`.

**Global state:** `src/context/AppContext.js` — single React Context + `useState` hooks wrapping the entire app. All business logic (habits, completions, challenges, settings, streaks) lives here. Each state key is persisted to its own AsyncStorage key and mirrored to Supabase with fire-and-forget upserts in `src/services/sync.js` (last-write-wins, no conflict resolution). On login, cloud data replaces local if the cloud has habits; otherwise local is pushed.

**AI coaching:** `src/services/aiCoaching.js` calls Supabase Edge Functions `generate-nudge` (daily, cached in `ai_nudges`), `generate-reflection` (weekly/monthly, cached in `ai_reflections`) and `suggest-habit` (Magic Fill in the habit form). All use `supabase/functions/_shared/ai.ts`: Haiku-class `AI_MODEL`, a cached `COACH_SYSTEM` block, and per-user daily quotas (`ai_usage` table + `ai_consume()` RPC, free vs Pro limits from `profiles.is_pro`; 429 `quota_exceeded`). Always pick the text block by type (`content.find(b => b.type === 'text')`): Haiku 5.5 may emit a thinking block first. The Anthropic key lives only in edge function secrets.

**Snackbar** (C-10, `src/components/ui/Snackbar.js`): `SnackbarProvider` wraps `AppNavigator` inside `AppProvider` (App.js) and `SnackbarView` sits above the tab bar (Android: full-width bar, 8 dp margins; iOS and the mockup: a floating pill). `useSnackbar()` is a stable `{ show(item), dismiss(match?), flush(), showing(kind) }` (no-op without the provider); `flush()` ends what shows as `'flush'` and resolves with its `onHide` result, and Settings awaits it before `signOut()` / `deleteAccount()` so a pending delete commits (and its cloud delete is awaited) while the session lives. `useSnackbarInset()` is the bottom padding a screen adds to its scroll content while one shows, held until the exit animation ends (Today, Habits, Challenges). Item: `{ message, actionLabel, onAction, onHide(reason), duration, endsOnBackground, kind }`. One at a time: a newer one replaces the shown one (bump 1.03 -> 1 on `spring.snappy`; the replaced one's `onHide('replaced')` runs). Timeout tokens in `motion.js` `snackbar` (standard 8 s, screenReader 10 s via `isScreenReaderOn()` in `src/utils/a11y.js`, short 4 s for the choreography-off per-check toast); the timer pauses while the bar is touched (web: also while the mouse is over it) and while any `overlayStatus` overlay (sheet, dialog) is open. The message is announced; the action's accessible name is "Undo: <message>" (`snackbar.actionA11y`); Undo announces "Undone". `onAction` runs on the action, `onHide(reason)` for timeout / replaced / dismissed / background / flush / unmount, so deferred commits go in `onHide`; a deferred delete ignores `'unmount'` (the provider is going away after sign-out, with no session), so the habit simply stays archived. **Day-complete resolution (C-07, plan §4.1 beat 7):** the check that completes the day sends a credit to the ring. `src/utils/creditAnchors.js` (pure module state) registers views by key through per-instance callback refs (`useAnchor(key)`; a detaching view only drops the key while it is still the registered one, so the token preview's extra headers cannot delete Today's): `check:<habitId>` on a card's check disc or done-pill ✓, `ring` / `strip` in TodayHeader, `ringSticky` / `sticky` in the sticky bar) and measures them with `measureInWindow`; `departurePoint` / CreditFlight `pickDeparture` decide the start (the check, or the strip's bottom edge when the card is off screen or under the sticky bar, §4.2). `CreditFlight` (always mounted, hidden, nothing re-renders) flies on the `creditDeparts` beat (+500): a 12 pt `signature` dot with a ✓ on a quadratic curve (`amount.creditCurve`: rises first, then sweeps in) to the strip ring, or the sticky-bar ring once stuck (TodayScreen `creditTargets`), as one native linear timing whose interpolation bakes in `easing.credit` (`Easing.bezier(0.3, 0, 0.1, 1)`: the accel handle out, the decel handle in), landing one frame before +750, so its end event never shares the frame with the day.complete haptic. It waits in the ring until the `resolution` beat fires, then fades over `duration.press` while the C-06b gold sweep starts; a cancelled resolution (un-check, a broken limit) takes it back mid-air. Mark the rest passes `creditFrom` (its changed ids in list order) and sends one credit from the bottom-most of them on screen. `RingBurst` (24 deterministic particles from `amount.burstFrom` x the ring radius, outside the stroke so nothing blends to olive, out to about `burstTo`; native; scaled to the ring that shows) plays on `resolution` until +1500; `TodayHeader` `RingPulse` scales the ring 1.06x (`amount.ringPulse`) on the same beat. Both layers sit in the Today body (inside the safe area), clip to it and have `pointerEvents="none"`, so taps during the burst land; an un-check or Undo calls `burstRef.stop()`. Both pre-connect their native animation graph at idle (`InteractionManager`, a no-op run), because the first native start cost ~100 ms of JS on the resolution beat. Reduced motion: no creditDeparts beat and no particles (the ring turns gold with a ✓). Choreography off: no flight; TodayScreen plays the burst at the tap. `src/hooks/useCelebrationQueue.js` orders the full-screen celebrations: the trophy opens on the beat grid (`openTrophyAt`: +500 after a check that completed a challenge, +1500 when it also completed the day, +125 with the flag off) and owns the sequence (while its timer is armed or it is up the milestone waits, and its timer clears a milestone timer due in the same batch); a streak milestone waits for the end of the moment (latest `resolution` tapAt + `MOMENT_MS`), or +875 outside one, for the trophy to close (`trophyDone`), and for Today to be the visible tab (`useTabActive`); `CompletionCelebration` grows its circle from the measured `originKey` ring and holds the Android back key while it is up (back or a tap closes it after `celebration.milestoneSkipAfter`, 1 s). The frame log adds `visual.credit` and a `perf.commit` mark (tap to commit of the tap's render, TodayScreen layout effect). Daily / quit card bodies pass `stateChange` to PressableScale: no ripple, and the pressed overlay only under reduced motion (C-06b carry S2).

**Hidden tabs (C-07 perf):** App.js memoises the five screens and renders each through `TabScope` (`createTabScope(AppContext)` in `src/utils/tabScope.js`): the active tab gets the live context value; an inactive one keeps its last value and catches up `MOMENT_MS` (1.5 s) after the first change it missed, at once on a theme change or when the app leaves the foreground. A check-off therefore renders Today only (release emulator: tap to commit 128 -> ~47 ms). When a pager drag starts, App.js passes `peek` to the two neighbours, so they show the live value under the finger. `useTabActive()` (from `src/utils/tabScope.js`, true outside a TabScope) tells a screen whether it is the visible tab: Habits opens deep-link sheets only while active, and Today holds the milestone screen. A tab requested while a slide runs is queued (`queuedTab` in App.js) instead of dropped. Code in a hidden screen still sees a context value up to 1.5 s stale.

**Motion:** `src/theme/motion.js` holds the §2.9 tokens (`duration` press 100 / state 200 / selection 150 / value 300 / enter 450 / reduced 150 / `exit(x)` = 0.7x; `beat` offsets on the 120 bpm grid 125/250/375/500/750/875 plus `b32` 62; `easing` standard / emphasizedDecel / emphasizedAccel; `spring` snappy / gentle / celebrate; `celebration` timings for the celebration layer). Never write `tension:`/`friction:`/`stiffness:`/`damping:` a literal `duration:`/`delay:`/`Animated.delay(<number>)`, `bounciness`/`speed`, or a `setTimeout(fn, <number>)` outside it (`src/theme/__tests__/motionTokens.test.js` fails; non-animation timers go in its `TIMER_ALLOWLIST` with a reason). Chain one overlay to the next with the close callback (a `ui/Sheet`'s `onDismiss` or `ref.requestClose(then)`, `HabitDetailSheet` `close(then)`, a `Dialog`'s `onDismiss`), never a timer tuned to an exit duration; `handoff.afterTabChange` covers a screen opening its sheet after a tab change. Components call `useMotion()` (tokens capped at 150 ms, `reduced` flag, `timing`, `springTo`; the sheet motion lives in `ui/Sheet`, which uses `sheetOut`); the plain helpers read the live setting via `isReducedMotion()` (`src/utils/a11y.js`, one shared `AccessibilityInfo` subscription; Android reads `transition_animation_scale == 0`). Reduced motion: sheets fade in place instead of sliding (`ui/Sheet` maps the sheet value to opacity over `SHEET_FADE_RANGE` 240, so a drag fades it), the Snackbar fades instead of sliding and never bumps (its exit always plays: the last one stays rendered until it finishes), a tab tap is a 150 ms fade of the pager row (swipes still page), springs become 150 ms timings, celebrations use their static variants; haptics and sound are unchanged.

**Type:** `src/theme/typography.js` is the §2.7 scale (`display` 34, `displayRing` 28, `numericSmall`, `title` 28, `headline`, `body`, `callout`, `footnote`, `caption` 12 = the floor). `numeric` (tabular figures) goes on digits that change in place or line up. Render with `<AppText variant>` (`src/components/ui/AppText.js`). Space Grotesk Bold (`assets/fonts/`, OFL, SHA-256 in its README) is loaded by `src/theme/fonts.js` through expo-font before first paint (AuthGate waits with the locale; 2.5 s timeout, after which the session stays on the system face) and is used only for `display`/`displayRing` numerals. Titles are system bold; to switch them set `VARIANT_FACE.title = 'spaceGrotesk'`. `familyFor` keeps non-Latin text and every non-numeral `ja` string in the system face, and a custom face never gets a fontWeight. `typeFloor.test.js` fails on any `fontSize` below 12.

## Data Models

- **Habit:** `{ id, name, icon (emoji|null), customIconUri, type ('daily'|'volume'|'timed'|'quit'|'atMost'), volumeGoal (units, minutes, or the limit), unit, schedule, color (hex|null; see Habit accents below), timeOfDay ('anytime'|'morning'|'afternoon'|'evening'), archived, sortOrder, reminder: { enabled, hour12, minute, ampm }, createdAt }`. `AppContext.habits` is the active ordered list; `allHabits`/`archivedHabits` include archived ones. Custom icons: `customIconUri` is a durable file under the document dir `habit-icons/<id>.jpg` and `iconStoragePath` the private Supabase Storage object `<uid>/<id>.jpg` (`src/services/icons.js`; AppContext re-downloads missing files and `HabitIcon` falls back to the emoji on error). `schedule` is `{ type: 'daily' }` | `{ type: 'weekdays', days: [0-6] }` | `{ type: 'perWeek', target: 1-6 }` (missing = daily). All schedule/streak rules live in `src/utils/schedule.js` and `src/utils/streaks.js` (pure, Jest-tested; the edge functions mirror them in `supabase/functions/_shared/schedule.ts`).
- **Habit accents** (`src/theme/accents.js`): 7 curated accents (coral, lime, teal, sky, magenta, pink, slate) with light/dark fills and opaque tints. Render a habit's colour only through `resolveAccent(habit.color, themeName)` → `{ id, fill, onFill, tint, ring }` (HabitCard, Habits rows, the widget, per-habit notification tint). A pick stores the accent's light-fill hex (`storedHexFor(id)`), never an id, so old app versions that draw `habit.color` raw keep working; legacy `HABIT_COLORS` hexes and unknown hexes are remapped at read time (`LEGACY_ACCENT_MAP`, else nearest allowed hue; null = sky, the new-habit default) and never rewritten. The habit form keeps `form.color` as stored until a dot is tapped (`src/utils/habitForm.js`). `suggest-habit` offers the same 7 hexes and drops anything else.
- **Completions:** keyed by `YYYY-MM-DD`, each date maps `habitId → count`. `notes` has the same shape with text values and rides on the `completions.note` column. `dailySnapshot` records which habits existed each day so history stays accurate.
- **Challenge:** `{ id, name, description, days, icon, completedDays[], completed, startDate, linkedHabitIds[] }`. Tier (platinum/gold/silver/copper) is computed at archive time from completedDays/days via `getChallengeTier`.
- **Moods:** `{ 'YYYY-MM-DD': 1-5 }` (`setMood`), synced to the `moods` table; insights in `src/utils/mood.js` (pure, tested) feed the Progress "Mood & habits" card.
- **Settings:** `{ theme, soundEnabled, hapticsEnabled, notificationsEnabled, reminders[], eveningReminder*, skips, streakFreezes, milestones, extras }`. Persistence (S-10):

  | Where | Keys | Rules |
  |---|---|---|
  | settings row, one column each | `theme`, `notificationsEnabled`, `soundEnabled`, `hapticsEnabled`, `reminders`, `eveningReminderEnabled/Hour/Minute`, `skips`, `streakFreezes`, `milestones` | cloud wins on a pull |
  | settings row, `extras` jsonb | `hints.{longPress, challengeTip, linkPrompt}` (`setHint(id)`), `milestonesBackfilled` (OR-merged across devices), `streakNewsEnabled` and any other key (`updateExtras(patch)`, cloud wins) | every new synced setting goes here, never a new top-level key (a jest round-trip check enforces it); unknown keys survive |
  | device-local `deviceSettings` object (`src/utils/deviceSettings.js`: `get/setDeviceSetting(s)`, `useDeviceSettings()`) | `badgeEnabled` (set once in the load: existing install true, new install false), `appOpens` (C-03: +1 per AppProvider load and per return after 30 min in the background, `src/utils/hints.js`; one-time tips wait for the 2nd open), `lastSeen` (C-09: `{ date, streak, freezesUsed, backOnBeat? }`; account-scoped: dropped on switch/delete/reset) | never synced or backed up |
  | device-local AsyncStorage keys (`DEVICE_LOCAL_KEYS` in `src/utils/storage.js`) | `deviceSettings`, `devFlags`, `dateOffset`, `locale`, `reviewPrompts` | survive `clearAll` (account switch, delete, Reset), except that Reset sets `dateOffset` back to 0; dev mode itself is in SecureStore |
  | per-account local bookkeeping (wiped by `clearAll`) | `hasOnboarded`, `accountCreatedAt`, `pendingChallengeRewards`, `lastBackupAt`, `widgetPendingSync`, `pendingUpserts`, `settingsExtrasDirty`, `lastUserId`/`accountWasDeleted` (sentinels) | not synced |

  `migrateSettings(cloud, local)` merges a pull (both cloud call sites use `setSettings(prev => migrateSettings(cloud, prev))`) and a backup import: columns are cloud/backup-wins, `extras` goes through `mergeExtras`, unknown top-level keys are dropped. The column comes from `supabase/migrations/20261018120000_settings_extras.sql`; until it is applied, `upsertSettingsRow` (sync.js) sees PGRST204, warns once in dev and sends the row without `extras` for the session, so extras then live only on the device (kept through pulls by the merge) and `settingsExtrasDirty` is set. After every pull merge, `writeBackSettings` (sync.js) pushes the merged settings once when the pulled row has the column and either its extras deep-differ from the merge or the dirty flag is set; the login push with no cloud habits merges the cloud's extras in first (`withCloudExtras`). `updateSettings`, `setHint` and `updateExtras` read `settingsRef` and use functional `setSettings`, so writes in one tick all land. `src/context/__tests__/settingsCallSites.test.js` pins the call sites. Backups carry `settings.extras` and none of the device keys.

## Key Behaviors

- "Today" uses `dateOffset` (from Settings dev tools) to simulate different dates during development.
- Goal rule lives in `src/utils/habits.js` `isGoalMet(habit, count)`: daily/quit need 1, volume/timed need >= goal (counts may exceed), atMost needs <= limit (untouched days count, bounded by `createdAt`). Use it everywhere instead of `count >= volumeGoal`; the edge functions mirror it as `goalMet`. Challenge templates (`CHALLENGE_TEMPLATES`) live there too. Today is logged from the card; past days via long-press (yesterday) or `setHabitCountOn`/`toggleHabitDoneOn`; never the future.
- Streak forgiveness: `settings.skips` ({date: [habitId]}, long-press "Skip today") and `settings.streakFreezes` (date list, 2 auto per month, reconciled in AppContext from the real date) are rest days for streak purposes (`isExcused`). Both sync via the settings row.
- Forgiveness moments (C-09): on a new real date since the device-local `lastSeen`, a one-time Today card (`StreakNewsCard`, above the first habit card on `brandSurface`, fades in, announced once) says "A freeze covered yesterday. Your 12-day streak holds." (a weekday name for an earlier day, pt-BR with its article; a date once it is a week back; "Freezes covered N days" for several) or "Your streak ended at 12 days. Today starts a new one." (runs of `RESET_MIN_STREAK` 2+, only while no new streak is running; action "Start today's first habit" while nothing is done today: dismisses it, announces "First up: <habit>" and scrolls the list up under the sticky bar when it starts below mid-screen; otherwise "Got it"). The pure `sinceLastOpen(prev, now)` in `src/utils/streaks.js` decides; AppContext runs it on the real date only once the data has settled (after a pull has succeeded this session, `pullOk`, so an offline start shows nothing and writes nothing; while no foreground pull is in flight, `pullsSettled`; and once `reconcileFreezes` would not change the freezes), keeps the card in memory (`streakNews`, `dismissStreakNews`; dropped on a date change) and updates `lastSeen` at once after every streak/freeze change, so in-session edits are never announced later. No retroactive cards: the first run on a device or account only records, a same-date run never fires, and a cloud pull never touches `lastSeen`, so a sign-out/in or a cold start does not bring a card back. A reset arms `lastSeen.backOnBeat`: the next check-off (or Mark the rest) on Today calls `takeBackOnBeat()` and shows "Back on beat." in the strip line like a small beat (Ionicons `musical-notes`, at `beat.b4`, announced, no sound of its own) and dismisses the reset card; a streak found running on a later date drops it. Opt-in "Streak news" (Settings → Notifications, native only, `settings.extras.streakNewsEnabled`, synced): while today (real date) would end missed, `requestStreakNews` (notifications.js, on the scheduling chain, id `streak-news-<tomorrow>`, `STREAK_NEWS_HOUR` 9:00) schedules tomorrow's note with the same copy (`streakNewsTonight`: a freeze left this month → it holds, else it ended). Every pass first cancels every pending `streak-news-*` by id prefix, so opening the app on a day drops that morning's note (the card has the news), and a done/rest day, the switch or the master switch off, and sign-out leave none; a widget check-off cancels them all too (`widgetTaskHandler`), and the next app open schedules a fresh one. `src/utils/__tests__/notifications-streakNews.test.js` runs the real module against a mocked expo-notifications. Dev tools (real date, since freezes ignore the offset; `src/utils/seed.js`): "Simulate missed yesterday" (`planMissedYesterday`: clears yesterday's check-offs, `lastSeen` back two days → the freeze card, or the reset card when no freeze is left) and "Use up freezes this month" (`planUseUpFreezes`: the 1st and 2nd become the month's two freezes with their check-offs cleared; disabled on the 1st and 2nd). Recipe: Seed perfect streak 13 → Simulate (freeze card) → Use up freezes → Simulate (reset card) → check a habit (Back on beat). The mockup never runs the check; `?streakNews=freeze|freezeDay|freezeMany|reset|back` (`mockup-shot.mjs --streakNews`) shows a sample card or holds the line. `?snackbar=markRest|skip|delete` (`--snackbar`) holds a sample C-10 Snackbar on Today (delete has a long two-line message).
- Streaks are computed on the fly; the overall streak counts a day only if every *scheduled* habit in that day's snapshot met its goal. Unscheduled days are rest days (chain preserved, no increment) and an unfinished today never breaks a streak. One "done" rule (`src/utils/dayStatus.js`, pure, tested) feeds streaks, Perfect Days, the heat map, the habit detail grid, the share cards and the widget: today always uses the live habit list (never the snapshot), past days their snapshot; `isHabitDoneOnDay` returns `'before'` ahead of a habit's `createdAt`, so that habit is left out of the day (a day with no habit yet is not drawn and never counts; for the streak walk it still ends the chain). `mergeSnapshots` never overwrites today. The demo / dev seed (`src/utils/seed.js` `buildSeed`) applies functional updates and backdates the seeded habits' `createdAt` to today - 31.
- Challenge days are auto-claimed from `TodayScreen` when all linked habits are done; expired challenges archive with a tiered reward modal. `autoClaimChallenges(countsAfter, { defer })` judges the post-action counts (`isHabitSatisfiedWith`) via the pure `planChallengeClaims` in `src/utils/challenges.js` and returns `{ claimedIds, completingIds }`.
- "Mark the rest done (N)" (below the last Today card, S-02; there is no Unmark All) sets only untouched, non-skipped daily/quit habits to 1 (`applyMarkRest` in `src/utils/habits.js`, `markRestDone` in AppContext); counters and limits are never touched. Its 8 s Snackbar Undo (`restoreHabitCounts` → pure `revertMarkRest`) puts back the previous value of each habit it marked that is still at 1, so edits made inside the window survive, and un-marks exactly the challenge days it claimed, all on the day stored with the snackbar. A challenge it would complete only has its day marked; the completion is queued and runs (trophy after) when the toast hides, re-checked against current state. Its snackbar is `endsOnBackground`, so backgrounding the app hides it and Undo never outlives the completion; a newer snackbar replacing it also closes the window. Un-checking, decrementing or skipping a linked habit inside the window cancels it. A single check-off still completes a challenge immediately.
- Celebrations (C-08): a perfect day resolves at the ring (credit flight + RingBurst, C-07); there is no perfect-day confetti. Streak milestones come in two kinds, recorded once ever in `settings.milestones` (`{ id: 'streak-N', days, date, small?, silent? }`) and queued via `pendingMilestone`: the big ones (`STREAK_MILESTONES` 7/30/100/365, Ionicons `icon` flame/ribbon/trophy/diamond) get the full-screen `CompletionCelebration`; the small beats (`SMALL_MILESTONES`: 1 = "Day 1. Your streak has started.", 3, 14; `small: true`) replace the strip's day line (and the sticky bar's greeting) for `celebration.smallBeatHold` (5 s) as an overlay on the strip surface, so the strip never changes height, are announced, play no sound of their own (a check-off's day.complete chord is theirs, §2.10; a Skip today that completes the day plays no chord, so its beat is silent), take two lines (on a short window the overlay also covers the top of the chip row), leave at once on an un-check, and never appear in the trophy case. No retroactive awards: `planMilestones` (`src/utils/milestones.js`) records silently (`silent: true`) every milestone the streak already passed when first computed after load, or that a pull, a past-day edit or a date change carries it across; on that first run a small beat at or below the best streak ever (`getBestStreak`, computed only while such a beat is open) is recorded silently too, so a returning user never hears "Day 1" or "3 days in a row". The login pull that applies cloud history resets the previous streak (`prevStreakRef = null` plus a `milestoneEpoch` bump), so the first evaluation on the pulled history backfills the same way (a new device or a reinstall), and `settings.milestones` merges as a union by id on a pull or backup import (`mergeMilestones` in `src/utils/settings.js`; `writeBackSettings` sends entries the row lacks), so a pull can never wipe a silent entry. It celebrates only when an armed action takes the streak across one (the highest crossed): a today check-off, un-check or Mark the rest (`incrementHabit`/`decrementHabit`/`markRestDone`), Skip today that completes the day (`toggleSkipHabitOn` on today, m2: milestones are once ever, so a silent record would lose the moment), a notification Done or `groov://habit/<id>/done` while `AppState` is `active` (m1; a cold start's initial URL records silently), and a notification Done from the background, whose moment waits in `deferredMilestoneRef` for the next foreground the same day (m5). Mark the rest's Undo (`restoreHabitCounts`) takes back a non-silent milestone dated today above the restored streak (and a pending celebration of it), so completing the day for real celebrates it again; TodayScreen also drops a queued milestone above the live streak and closes an open milestone screen when the streak falls below it (an Undo landing after the queue fired). The arm (`createMilestoneArm`) holds the completions and today's skips it started from and is consumed only by the first effect run that sees newer ones (stale-run guard). `CompletionCelebration` is a root `OverlayModal` (`heavyScrim`, translucent bars, covers the tab bar, takes back): the `brandGround` grows from the measured ring, `theme.celebration` confetti, the milestone's Ionicons mark on a `brandGroundCta` disc, the streak as a Space Grotesk `display` numeral ("7 / days in a row", no exclamation mark), "Share your streak" (enabled after the 1 s guard; closes, then TodayScreen opens `ShareCards` on the streak card from `onHidden`, which runs once the Modal has gone: iOS `onDismiss` with a `celebration.hiddenFallback` 500 ms fallback, else two frames after the hide; once only; Share sits at 50 % opacity during the guard) and "Tap to continue"; a tap, back or the escape gesture closes it after 1 s; it closes itself after `celebration.autoDismissAt` (6 s) unless a screen reader is on; accessibility focus moves to the headline (announced only when focus cannot be set); reduced motion = the ground fades in and out over 150 ms with no circle or confetti. `TrophyCelebration` is for challenge completion (a root `Modal`, so its scrim covers the tab bar; a tap or the back key dismisses it once it has been up 1 s, otherwise it closes itself). The Progress trophy case lists the big milestones and challenge medals. Settings → Dev tools → "Seed perfect streak" (0/2/6/13/29, `buildPerfectStreak` in `src/utils/seed.js`) writes N perfect days ending yesterday for the current habits, moves their `createdAt` to the start of the run, clears today and drops recorded milestones above N, so checking every habit crosses N + 1 (0 = Day 1, 2 = the 3-day beat, 6 = the 7-day screen); it syncs to the cloud. The mockup's `?celebrate=<days>` (`mockup-shot.mjs --celebrate`) holds that milestone screen or beat for stills.
- Tinted surfaces are opaque: done and over-limit habit cards pre-mix the habit colour over `theme.surface` with `mixHex` (`src/utils/color.js`); they and skipped (translucent) cards drop elevation, because Android draws the shadow through a translucent fill. The habit-detail grid shows today, not yet done, as a neutral outline (`gridDayStatus` → `pending`, with a legend entry), never red.
- `accountCreatedAt` (the first day Progress, the heatmap and the habit detail grid show) comes from `deriveAccountCreatedAt` in `src/utils/accountCreatedAt.js` (pure, tested): the earliest of the stored value, the first logged completion and the earliest habit `createdAt`, never in the future. It is derived on cold start, recomputed and saved after the login pull (the stored value is dropped on an account switch), and the foreground delta pull can only lower it to real history.
- Date keys must be local dates; several places still use `toISOString()` (UTC) and are tracked as a bug.
- Android font scale: React Native already scales `fontSize` and `lineHeight` (Android's non-linear sp curve), so type tokens never multiply by `fontScale` in JS. A system font-size change while the app is alive is handled by the config plugin `plugins/withFontScaleConfigChange.js` (#190): it turns on RN's `enableFontScaleChangesUpdatingLayout` flag in MainApplication and adds `fontScale` to MainActivity's `configChanges`, so Fabric measures all text again. Without it, cached measurements keep the old scale and text clips until a cold start. Native change: rebuild with `rm -rf android && bash scripts/run-android.sh`. To test, change `adb shell settings put system font_scale 1.3` while the app is running, no restart needed. Delete the plugin once the installed React Native defaults `enableFontScaleChangesUpdatingLayout` to true (`ReactNativeFeatureFlagsDefaults.h`).
