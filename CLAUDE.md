# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

**Start dev server (Expo Go / QR code):**
```powershell
npm start
```

**Run on specific platform:**
```powershell
npm run android   # Android emulator (AVD "groov_pixel") or device
npm run ios       # iOS simulator (macOS only; this machine is Windows, use EAS builds)
npm run web       # Browser
```

> On Windows, if `npm` is not found in a new terminal, refresh PATH first:
> `$env:PATH = [System.Environment]::GetEnvironmentVariable("PATH","Machine") + ";" + [System.Environment]::GetEnvironmentVariable("PATH","User")`

> Always refer to versioned Expo docs at https://docs.expo.dev/versions/v54.0.0/ before writing Expo-specific code.

**Local env:** `.env.local` (gitignored) holds `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY`. `EXPO_PUBLIC_APTABASE_KEY` turns on anonymous product analytics via `src/utils/analytics.js` (`track(Events.X, props)`; no-op without the key; events are counts only, never names/ids; the privacy policy lists Aptabase). The same values are inlined in `eas.json` for production builds. `EXPO_PUBLIC_SENTRY_DSN` turns on crash reporting via `src/utils/sentry.js` (Sentry org `isaac-23`, project `groov`; the DSN is public and lives in eas.json); without it Sentry is a no-op. Source-map upload uses the `@sentry/react-native/expo` plugin in app.json (org `isaac-23`, project `groov`) plus the `SENTRY_AUTH_TOKEN` EAS environment variable (set for production and preview); local builds skip the upload because the token is not present locally.

**Quick compile check (no device):** `npx expo export --platform web --output-dir $env:TEMP\groov-web-export`

## Stack

- **Expo SDK 54** / React Native 0.81.5 / React 19.1.0, JavaScript (tsconfig exists but all files are `.js`)
- No file-based routing; no React Navigation library (custom pager in `App.js`)
- **Supabase** for auth and cloud sync (`@supabase/supabase-js`), AsyncStorage as the local-first store
- Sound kit (plan §2.11, F-04b): a synthesised "soft kalimba" (partials 1 / 2.76 / 5.4 plus a 9x click, each with its own decay) on one C-major pentatonic ladder. `src/utils/synth.js` (pure synth + WAV encoder) and `src/utils/soundKit.js` (pure: `SOUND_DEFS`, `EVENT_SOUNDS` event → sound or explicit null, `soundIdFor(event, { n } | { step, goal })`; daily check-offs climb `H(n)`, counters climb `C(k, G)` and the goal step is C6→E6, never lower; atMost limits get a flat quiet C5 tick and no sound on the tap that breaks the limit) are shared by the app and `node scripts/render-sound-kit.mjs` (writes the 12 listening WAVs + a day sequence to `research_notes/uiux/review/sounds/`, no expo-audio). `src/utils/sounds.js` `playSound(id)`: native renders each sound once to `cacheDirectory/groov-snd-<id>-<hash>.wav` (hash of the definition, so kit edits re-render; byte-identical to the Node render) and plays it with expo-audio (max 3 players, oldest released). AppContext starts `feedback.prewarmSounds()` once loaded: after `InteractionManager` + 4 s it renders the kit (chord, habit-1, goal, challenge, fanfare first, one per macrotask, postponed while any feedback event or sound happened in the last 1.5 s) and sweeps stale `groov-snd-*` files; a missing sound still renders on demand. Writes go to `.tmp` then rename, a wrong-size cache file is re-rendered, a write/play failure mutes that id for the session and warns once; web plays the same samples through a Web Audio buffer. No audio assets. The audio mode is iOS ambient (`playsInSilentMode: false` + `mixWithOthers`), so the silent switch mutes the kit
- Haptics and event sounds go through `src/services/feedback.js` only (the only importer of `expo-haptics`; a source test enforces it). Callers name the event, `feedback.play(EVENTS.habitDone)` (`habit.done`, `counter.step`, `habit.undone`, `challenge.claimed`, `day.complete`, `milestone`, `trophy`, `markRest`, `selection`, `toggle.on/off` via `feedback.toggled(v)`, `longPress`, `refused`, `error`, `destructiveConfirm`), and the plan §2.10 map picks the call: iOS impact/notification/selection, Android only `performAndroidHapticsAsync` with a `Platform.Version` fallback chain (Confirm/Reject/Gesture_End need API 30, Segment_Tick/Toggle_* API 34, else Context_Click/Clock_Tick/Long_Press, else nothing; never `Vibration`). Each event's sound comes from `soundKit.js` (pass `{ tone }` for the ladder note; `sound.preview` is the Settings → Sounds preview; Mark the rest plays its chord at +750; tap sounds are limited to one start per 60 ms, celebrations never dropped). AppContext calls `feedback.configure({ haptics, sound })` on load, on settings changes and synchronously in `updateSettings`, so callers never check `settings.hapticsEnabled`/`soundEnabled`. 40 ms haptic rate limit; `day.complete` lands at +750 ms and `challenge.claimed` at +250 ms by default (`{ delay }` overrides). Settings → Dev tools → Feedback log shows the last 50 entries with their offset from the tap; on the emulator `adb shell dumpsys vibrator_manager` lists each `performHapticFeedback(constant=N)`
- expo-notifications for local per-habit and global reminders. Categories give reminders Done / Snooze 1h buttons (handled in AppContext via `listenForNotificationResponses`); per-habit reminders back off after 3 consecutive missed days (`reminderDueWithBackoff`); AppContext schedules through `requestReminderSchedule` (debounced by `REMINDER_SCHEDULE_DEBOUNCE_MS`, one pass at a time, stale passes stop before their next OS call) so an older pass can never re-add a reminder a newer one cancelled; the evening smart check-in (`requestEveningCheckIn`) runs on the same chain, and the AppProvider unmount (sign-out) queues `clearRemindersOnSignOut` so the old user's reminders stop firing; the OS permission dialog is always preceded by `NotificationPrimer` via `ensureNotificationPermission()` (the primer is rendered above the onboarding gate in `App.js`, so onboarding can await it); AppContext exposes `notificationPermission` (refreshed on load and on foreground), and while permission is missing Settings shows the master row and every stored-on reminder as "Off · Tap to allow" (the master row asks; child switches are dimmed); global reminders (`DEFAULT_REMINDERS` in `src/utils/settings.js`, with `migrateSettings`) start off on a new install; the app badge shows habits left today
- `@react-native-community/datetimepicker` (8.4.4) for reminder times
- react-native-svg for the progress ring; charts and heatmap are hand-built (no chart library installed)
- expo-apple-authentication, expo-web-browser, expo-linking, expo-crypto for social sign-in

## Architecture

**Entry point:** `index.js` → `registerRootComponent(App)` → `App.js`

**Gating order:** `ErrorBoundary` → `AuthProvider` → `AuthGate` (no session renders `AuthScreen`) → `AppProvider` (keyed by user id) → `OnboardingScreen` until `hasOnboarded` → tab navigator.

**Navigation:** Custom slide navigator in `App.js`. Deep links (`src/utils/links.js`): `groov://today|progress|challenges|habits|settings`, `groov://habits/new`, `groov://habit/<id>` (detail sheet), `groov://habit/<id>/done`, `groov://dev/design` (token preview, dev/mockup only); AppContext parses them (initial URL + `url` events + `expo-quick-actions` home-screen shortcuts) into `requestedTab` and a `pendingRoute` the Habits screen consumes. All 5 screens are rendered simultaneously in a horizontal `Animated.View`; inactive screens have `pointerEvents="none"` and are hidden from screen readers (`importantForAccessibility="no-hide-descendants"`, `accessibilityElementsHidden`, and `aria-hidden` for web). Android back: every overlay is a `Modal` with `onRequestClose` (it consumes the event); otherwise a `BackHandler` in `AppNavigator` sends a non-Today tab to Today, and back on Today exits. Navigation is driven by swipe gestures (`PanResponder`) and tab-bar taps. Tab order: Today → Progress → Challenge → Habits → Settings. Screens can request a tab via `requestedTab`; swiping is disabled while `modalOpen`.

**Auth:** `src/context/AuthContext.js`. Email/password (with OTP password reset), Sign in with Apple (iOS/iPadOS only, native sheet + `signInWithIdToken` with nonce), Google (Supabase OAuth in the system browser, PKCE, redirect `groov://auth/callback`), and guest accounts (`signInAnonymously`; Supabase anonymous sign-ins + manual linking are enabled). Guests link later from Settings via `LinkAccountSheet` (`linkEmail` = `updateUser`, `linkWithGoogle`/`linkWithApple` = `linkIdentity`), keeping the same user id. Exposes `authProvider` (`email|apple|google|anonymous`), `isAnonymous` and `appleAvailable`. A pg_cron job purges anonymous users idle for 90 days. Account deletion calls the `delete-account` edge function. Setup steps: `docs/AUTH_SETUP.md`.

**Global state:** `src/context/AppContext.js` — single React Context + `useState` hooks wrapping the entire app. All business logic (habits, completions, challenges, settings, streaks) lives here. Each state key is persisted to its own AsyncStorage key and mirrored to Supabase with fire-and-forget upserts in `src/services/sync.js` (last-write-wins, no conflict resolution). On login, cloud data replaces local if the cloud has habits; otherwise local is pushed.

**AI coaching:** `src/services/aiCoaching.js` calls Supabase Edge Functions `generate-nudge` (daily, cached in `ai_nudges`), `generate-reflection` (weekly/monthly, cached in `ai_reflections`) and `suggest-habit` (Magic Fill in the habit form). All use `supabase/functions/_shared/ai.ts`: Haiku-class `AI_MODEL`, a cached `COACH_SYSTEM` block, and per-user daily quotas (`ai_usage` table + `ai_consume()` RPC, free vs Pro limits from `profiles.is_pro`; 429 `quota_exceeded`). Always pick the text block by type (`content.find(b => b.type === 'text')`): Haiku 5.5 may emit a thinking block first. The Anthropic key lives only in edge function secrets.

**Screens** (`src/screens/`):
- `AuthScreen` — login / register / forgot / reset modes plus Apple and Google buttons
- `TodayScreen` — greeting, progress ring, habit list, AI nudge card, challenge mini-cards, celebrations
- `ProgressScreen` — stat tiles, 7-day bar chart, 7/30/90-day heatmap with day detail, AI reflection card
- `ChallengeScreen` — active & archived challenges (max 3 concurrent), create/edit sheet
- `HabitsScreen` — create/edit/delete habits, per-habit reminders, emoji or photo icons
- `SettingsScreen` — theme, notifications, haptics, account, data, hidden dev tools (date offset, seed history, feedback log)
- `OnboardingScreen` — first-run flow: 2 intro slides, starter-habit picker (`STARTER_HABITS`), per-habit time-of-day + implementation intention (`habit.intention`, "After I …"), a Reminders step (each habit gets a reminder at its time of day via `reminderTimeForTimeOfDay`: morning 08:00, afternoon 13:00, evening 20:00, anytime none; "Turn on reminders" asks through the primer, "Not now" saves them off; skipped on web and when every habit is anytime, and the dots then count 4), then `completeOnboarding(habits)` creates them plus the 3-Day Kickstart (rendered outside the navigator)

**Components** (`src/components/`): shared primitives in `ui/` (`Dialog` for centred dialogs, `ActionSheet` for option menus: `ActionSheetIOS` on iOS, a bottom list with Cancel on Android/web; use it instead of a multi-button `Alert`, which on Android drops the 4th button and ignores back), `HabitCard`, `HabitDetailSheet` (per-habit grid/stats, opened from the Habits list), `ShareCards` (Progress → Share: streak / week / year-in-pixels cards captured with react-native-view-shot and handed to expo-sharing), `ProgressRing` (SVG), `TimePicker` (native `@react-native-community/datetimepicker`: the system time dialog on Android via `DateTimePickerAndroid.open`, which follows the device 12/24-hour setting; a spinner in the app card with Cancel/Save on iOS; `TimePicker.web.js` keeps the custom wheel for web and the mockup because the package has no web code; results stay `{ hour12, minute, ampm }` via `timeToDate`/`from24h` in `src/utils/time.js`. Native module, so changing it needs a dev-client rebuild), `BottomSheet`, `SheetHeader`, `EmptyCard`, `Slider`, `TrophyCelebration`, `CelebrationOverlay`, `CompletionCelebration`, `ChallengeRewardModal`. Shared UI primitives live in `src/components/ui/`: `Dialog` (centred `Modal` with fade, `statusBarTranslucent`, `onRequestClose` so Android back closes it, `KeyboardAvoidingView`, `accessibilityViewIsModal`; props `visible`, `onClose`, `title`, `body`, `actions[{label, onPress, variant: 'secondary'|'primary'|'destructive', loading, loadingLabel, disabled}]` with Cancel first (primary = `action`/`onAction`, destructive = `dangerFill`/`onDanger`, every disabled action dimmed), `layout` (`auto` stacks the buttons full-width, main action on top, for 3+ actions or a label over 16 characters; `row`/`stack` force it), `dismissable` (also gates scrim tap and the VoiceOver escape), `destructive` (legacy: all primary actions destructive), `initialFocusRef` instead of `autoFocus`, which does not fire inside an Android Modal (focus at 150 ms, one retry at 300 ms), and `onDismiss`, which runs once the dialog has gone, so follow-up `Alert`s go there rather than in the same tick as closing). Component render tests use `react-test-renderer`; jest's `moduleNameMapper` pins `react-native/*` to the top-level package because a nested `react-native` copy under `node_modules/react-native/node_modules` otherwise breaks native-component mocks. Every scrimmed overlay renders `ui/OverlayModal` instead of RN `Modal`: it registers with `src/utils/overlayStatus.js` so App.js switches the status bar to light icons in dark mode while a scrim is up, and on Android, only when that would change the style (`overlayChangesStatusBar()`, set by App.js: dark Today), opens the Modal two frames late, because RN's Modal window copies the activity's status-bar appearance only when it is created. Pressables (F-06): `ui/PressableScale` is the press model (0.97 scale over `duration.press`, `spring.snappy` release, Android `android_ripple` with `theme.ripple` + `foreground`, a `pressedOverlay` on iOS/web and under reduced motion, where it never scales; `disabled` keeps it focusable and routes taps to `onDisabledPress`; `hitSlopFor(w, h)` = `max(0, (touchMin - visual) / 2)`, touchMin 48 Android / 44 iOS+web). `ui/Button` (`variant` primary|secondary|tertiary|destructive, `filled`, `size` md 48 | sm 40 + slop, `block`, `icon`, `loading`; a disabled tap plays `refused` unless `onDisabledPress` is given) and `ui/IconButton` (Ionicons `icon`, 40 visual, borderless ripple, slop to the touch minimum; `accessibilityLabel` is required and a jest source check enforces it). Both are silent on an enabled press (§2.10). The ui primitives read the theme from `src/theme/ThemeContext.js` (a memoized `{ theme, themeName }` that AppProvider provides; light outside the provider), never `useApp`, so they do not re-render on every app-state change and stay light to import and test. `onDisabledLongPress` lets a disabled control inside a larger surface still open its options (HabitCard's − at 0); a bounded Android ripple on a rounded control gets `overflow: 'hidden'` automatically. New pressables use these instead of `TouchableOpacity`. Informational cards (Tip, Magic Fill, AI nudge) use `brandSurface`, not the selection pair. Sheets sit on `raised`, dialogs on `overlay`. The scrim colour is the `scrim` theme token

**Utilities** (`src/utils/`): `storage.js` (AsyncStorage wrappers), `backup.js` (JSON backup build/validate/merge; `src/services/backup.js` does the share sheet / document picker, Settings → Backup), `supabase.js` (client, PKCE), `synth.js` / `soundKit.js` / `sounds.js` (sound kit), `notifications.js`; `src/services/feedback.js` is the single haptics/sound gate

**Groov Pro** (`src/services/entitlements.js`, `PaywallSheet`): `isPro` = `profiles.is_pro` (set by the `revenuecat-webhook` edge function, secret `REVENUECAT_WEBHOOK_SECRET`) or a live RevenueCat `pro` entitlement. `react-native-purchases` only initialises when `EXPO_PUBLIC_REVENUECAT_ANDROID_KEY` / `_IOS_KEY` are set; otherwise the paywall shows a "coming soon" note. Free limits in `FREE_LIMITS` (5 active habits, 1 global reminder); gate with `canAddHabit()` / `canAddReminder()` which open the paywall via `openPaywall(reason)`. AI quotas (`ai_usage`) use the same flag server-side.

**Android widget** (`src/widgets/`): `react-native-android-widget` provider `GroovToday` (app.json plugin). `widgetData.js` builds today's model from AsyncStorage (pure, tested) and `applyWidgetToggle` writes check-offs back plus a `widgetPendingSync` queue the app flushes to Supabase; `TodayWidget.js` is the Flex/TextWidget tree; `widgetTaskHandler.js` is registered in `index.js` (headless, so Metro reload does not update it, cold-start the app); `refreshWidget.js` is called from AppContext on data changes. Settings → About has "Add home-screen widget" (`requestPinWidget`).

**Localization** (`src/i18n/`): `i18n-js` + `expo-localization`. `t(key, params)` with `%{name}` interpolation and `{ one, other }` plurals via `count`; locales en, es, de, fr, pt-BR, ja in `src/i18n/locales/*.json` (every file must have exactly the key set of `en.json`, a test enforces it). `initLocale()` is awaited before first paint (`App.js`, and in the widget task handler); `setLocale(code|null)` persists the Settings → Language choice (null = follow the device via `matchSupportedLocale`); components that render text call `useLocale()` to re-render on change. Data-like strings (`STARTER_HABITS`, `CHALLENGE_TEMPLATES`) expose translated getters / `getStarterHabits()` / `getChallengeTemplates()`; stored habit names are copied at creation and never re-translated. Dates use `toLocaleDateString(getLocale(), …)`. Copy follows `docs/GLOSSARY.md` (one term per concept in all 6 locales, tone rules, per-locale formality and punctuation, brand-phrase transcreations, a "Don't say" list); `src/i18n/__tests__/glossary.test.js` fails on retired terms.

**Theme:** design tokens live in `src/theme/tokens.js` (pure: `palette.light|dark` role colours, `accents`, `data` ramp, `brand`, `space`, `radius`, `size`, `elevation`, and `pairs`, the declared fg/bg contrast pairs of plan §2.5); `contrast.js` has the WCAG helpers (`contrastRatio`, `mix`, `hueOf`; accepts rgba); `accents.js` holds the 7 habit accents and `LEGACY_ACCENT_MAP`. `colors.js` is the adapter screens read as `theme.<key>`: every role plus the legacy keys (`textMuted`, `primary`, `primaryLight`, `danger`, `warning`, `tabIcon*`, ...) mapped to their nearest role. New code reads role keys only, never hex. Since F-02 no file reads a legacy key: action fills use `action`/`onAction` (ink on the dark `#818CF8`); selected chips, segments and rows `selection`/`onSelection`/`selectionBorder`; indigo progress fills, bars and done cells `meter`/`onMeter`; indigo text and icons `link`; a glyph on a habit colour `onAccent`; Switches `switchColors(theme, on)` in SettingsScreen; onboarding the `brandGround*` roles (indigo in light, deep indigo with a `#818CF8` CTA in dark). Ratchets: `src/theme/__tests__/noHexLiterals.test.js` (hex/rgba literals outside `src/theme/`) and `legacyTokens.test.js` (legacy-key reads, including `themes.dark.<key>`, bracket reads and destructuring; baseline now empty) are per-file ratchets whose counts may only fall; after lowering one, run `UPDATE_RATCHET=1 npx jest src/theme` and commit the baseline JSON. `tokens.test.js` checks every pair's ratio. Dev builds and the mockup open a token preview at `groov://dev/design` (`src/screens/DesignPreview.js`). The in-app theme is Light / Dark / Auto in Settings.

**Motion:** `src/theme/motion.js` holds the §2.9 tokens (`duration` press 100 / state 200 / value 300 / enter 450 / reduced 150 / `exit(x)` = 0.7x; `beat` offsets on the 120 bpm grid 125/250/375/500/750/875 plus `b32` 62; `easing` standard / emphasizedDecel / emphasizedAccel; `spring` snappy / gentle / celebrate; `celebration` timings for the celebration layer). Never write `tension:`/`friction:`/`stiffness:`/`damping:` a literal `duration:`/`delay:`/`Animated.delay(<number>)`, `bounciness`/`speed`, or a `setTimeout(fn, <number>)` outside it (`src/theme/__tests__/motionTokens.test.js` fails; non-animation timers go in its `TIMER_ALLOWLIST` with a reason). Chain one overlay to the next with the close callback (`sheetOut(v).start(cb)`, `HabitDetailSheet` `close(then)`, ChallengeScreen `sheet.close(cb)`), never a timer tuned to an exit duration; `handoff.afterTabChange` covers a screen opening its sheet after a tab change. Components call `useMotion()` (tokens capped at 150 ms, `reduced` flag, `timing`, `springTo`, `sheetIn`/`sheetOut`/`sheetSettle`/`sheetStyle`); the plain helpers read the live setting via `isReducedMotion()` (`src/utils/a11y.js`, one shared `AccessibilityInfo` subscription; Android reads `transition_animation_scale == 0`). Reduced motion: sheets fade in place instead of sliding (BottomSheet maps the sheet value to opacity over `SHEET_FADE_RANGE` 240, so a drag fades it; `OverlayModal` turns `animationType="slide"` into `fade`), the UndoToast fades (its exit always plays: the last toast stays rendered until it finishes), a tab tap is a 150 ms fade of the pager row (swipes still page), springs become 150 ms timings, celebrations use their static variants; haptics and sound are unchanged.

**Type:** `src/theme/typography.js` is the §2.7 scale (`display` 34, `displayRing` 28, `numericSmall`, `title` 28, `headline`, `body`, `callout`, `footnote`, `caption` 12 = the floor). `numeric` (tabular figures) goes on digits that change in place or line up. Render with `<AppText variant>` (`src/components/ui/AppText.js`). Space Grotesk Bold (`assets/fonts/`, OFL, SHA-256 in its README) is loaded by `src/theme/fonts.js` through expo-font before first paint (AuthGate waits with the locale; 2.5 s timeout, after which the session stays on the system face) and is used only for `display`/`displayRing` numerals. Titles are system bold; to switch them set `VARIANT_FACE.title = 'spaceGrotesk'`. `familyFor` keeps non-Latin text and every non-numeral `ja` string in the system face, and a custom face never gets a fontWeight. `typeFloor.test.js` fails on any `fontSize` below 12.

## Data Models

- **Habit:** `{ id, name, icon (emoji|null), customIconUri, type ('daily'|'volume'|'timed'|'quit'|'atMost'), volumeGoal (units, minutes, or the limit), unit, schedule, color (hex|null; see Habit accents below), timeOfDay ('anytime'|'morning'|'afternoon'|'evening'), archived, sortOrder, reminder: { enabled, hour12, minute, ampm }, createdAt }`. `AppContext.habits` is the active ordered list; `allHabits`/`archivedHabits` include archived ones. Custom icons: `customIconUri` is a durable file under the document dir `habit-icons/<id>.jpg` and `iconStoragePath` the private Supabase Storage object `<uid>/<id>.jpg` (`src/services/icons.js`; AppContext re-downloads missing files and `HabitIcon` falls back to the emoji on error). `schedule` is `{ type: 'daily' }` | `{ type: 'weekdays', days: [0-6] }` | `{ type: 'perWeek', target: 1-6 }` (missing = daily). All schedule/streak rules live in `src/utils/schedule.js` and `src/utils/streaks.js` (pure, Jest-tested; the edge functions mirror them in `supabase/functions/_shared/schedule.ts`).
- **Habit accents** (`src/theme/accents.js`): 7 curated accents (coral, lime, teal, sky, magenta, pink, slate) with light/dark fills and opaque tints. Render a habit's colour only through `resolveAccent(habit.color, themeName)` → `{ id, fill, onFill, tint, ring }` (HabitCard, Habits rows, the widget, per-habit notification tint). A pick stores the accent's light-fill hex (`storedHexFor(id)`), never an id, so old app versions that draw `habit.color` raw keep working; legacy `HABIT_COLORS` hexes and unknown hexes are remapped at read time (`LEGACY_ACCENT_MAP`, else nearest allowed hue; null = sky, the new-habit default) and never rewritten. The habit form keeps `form.color` as stored until a dot is tapped (`src/utils/habitForm.js`). `suggest-habit` offers the same 7 hexes and drops anything else.
- **Completions:** keyed by `YYYY-MM-DD`, each date maps `habitId → count`. `notes` has the same shape with text values and rides on the `completions.note` column. `dailySnapshot` records which habits existed each day so history stays accurate.
- **Challenge:** `{ id, name, description, days, icon, completedDays[], completed, startDate, linkedHabitIds[] }`. Tier (platinum/gold/silver/copper) is computed at archive time from completedDays/days via `getChallengeTier`.
- **Moods:** `{ 'YYYY-MM-DD': 1-5 }` (`setMood`), synced to the `moods` table; insights in `src/utils/mood.js` (pure, tested) feed the Progress "Mood & habits" card.
- **Settings:** `{ theme, soundEnabled, hapticsEnabled, notificationsEnabled, reminders[], eveningReminder* }`. `dateOffset` is stored separately (dev tool).

## Key Behaviors

- "Today" uses `dateOffset` (from Settings dev tools) to simulate different dates during development.
- Goal rule lives in `src/utils/habits.js` `isGoalMet(habit, count)`: daily/quit need 1, volume/timed need >= goal (counts may exceed), atMost needs <= limit (untouched days count, bounded by `createdAt`). Use it everywhere instead of `count >= volumeGoal`; the edge functions mirror it as `goalMet`. Challenge templates (`CHALLENGE_TEMPLATES`) live there too. Today is logged from the card; past days via long-press (yesterday) or `setHabitCountOn`/`toggleHabitDoneOn`; never the future.
- Streak forgiveness: `settings.skips` ({date: [habitId]}, long-press "Skip today") and `settings.streakFreezes` (date list, 2 auto per month, reconciled in AppContext from the real date) are rest days for streak purposes (`isExcused`). Both sync via the settings row.
- Streaks are computed on the fly; the overall streak counts a day only if every *scheduled* habit in that day's snapshot met its goal. Unscheduled days are rest days (chain preserved, no increment) and an unfinished today never breaks a streak. One "done" rule (`src/utils/dayStatus.js`, pure, tested) feeds streaks, Perfect Days, the heat map, the habit detail grid, the share cards and the widget: today always uses the live habit list (never the snapshot), past days their snapshot; `isHabitDoneOnDay` returns `'before'` ahead of a habit's `createdAt`, so that habit is left out of the day (a day with no habit yet is not drawn and never counts; for the streak walk it still ends the chain). `mergeSnapshots` never overwrites today. The demo / dev seed (`src/utils/seed.js` `buildSeed`) applies functional updates and backdates the seeded habits' `createdAt` to today - 31.
- Challenge days are auto-claimed from `TodayScreen` when all linked habits are done; expired challenges archive with a tiered reward modal. `autoClaimChallenges(countsAfter, { defer })` judges the post-action counts (`isHabitSatisfiedWith`) via the pure `planChallengeClaims` in `src/utils/challenges.js` and returns `{ claimedIds, completingIds }`.
- "Mark the rest done (N)" (below the last Today card, S-02; there is no Unmark All) sets only untouched, non-skipped daily/quit habits to 1 (`applyMarkRest` in `src/utils/habits.js`, `markRestDone` in AppContext); counters and limits are never touched. Its 8 s toast Undo (`restoreHabitCounts` → pure `revertMarkRest`) puts back the previous value of each habit it marked that is still at 1, so edits made inside the window survive, and un-marks exactly the challenge days it claimed, all on the day stored in the toast. A challenge it would complete only has its day marked; the completion is queued and runs (trophy after) when the toast hides, re-checked against current state. Backgrounding the app hides the toast (`endMarkRestWindow`), so Undo never outlives the completion. Un-checking, decrementing or skipping a linked habit inside the window cancels it. A single check-off still completes a challenge immediately.
- Celebrations: a perfect day gets a light confetti burst only. The full-screen `CompletionCelebration` is reserved for streak milestones (`STREAK_MILESTONES` 7/30/100/365, recorded in `settings.milestones`, queued via `pendingMilestone`) and `TrophyCelebration` for challenge completion (a root `Modal`, so its scrim covers the tab bar; a tap or the back key dismisses it once it has been up 1 s, otherwise it closes itself). The Progress trophy case lists earned milestones and challenge medals.
- Tinted surfaces are opaque: done and over-limit habit cards pre-mix the habit colour over `theme.surface` with `mixHex` (`src/utils/color.js`); they and skipped (translucent) cards drop elevation, because Android draws the shadow through a translucent fill. The habit-detail grid shows today, not yet done, as a neutral outline (`gridDayStatus` → `pending`, with a legend entry), never red.
- `accountCreatedAt` (the first day Progress, the heatmap and the habit detail grid show) comes from `deriveAccountCreatedAt` in `src/utils/accountCreatedAt.js` (pure, tested): the earliest of the stored value, the first logged completion and the earliest habit `createdAt`, never in the future. It is derived on cold start, recomputed and saved after the login pull (the stored value is dropped on an account switch), and the foreground delta pull can only lower it to real history.
- Date keys must be local dates; several places still use `toISOString()` (UTC) and are tracked as a bug.
- Android font scale: React Native already scales `fontSize` and `lineHeight` (Android's non-linear sp curve), so type tokens never multiply by `fontScale` in JS. A system font-size change while the app is alive is handled by the config plugin `plugins/withFontScaleConfigChange.js` (#190): it turns on RN's `enableFontScaleChangesUpdatingLayout` flag in MainApplication and adds `fontScale` to MainActivity's `configChanges`, so Fabric measures all text again. Without it, cached measurements keep the old scale and text clips until a cold start. Native change: rebuild with `rm -rf android && bash scripts/run-android.sh`. To test, change `adb shell settings put system font_scale 1.3` while the app is running, no restart needed. Delete the plugin once the installed React Native defaults `enableFontScaleChangesUpdatingLayout` to true (`ReactNativeFeatureFlagsDefaults.h`).
